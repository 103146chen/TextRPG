## 0. 現況 vs 目標（先對齊落差）

| 面向 | 織夢現況 | 參考目標 |
|------|---------|---------|
| 版面 | 工具列 + 窄側欄（問題/Flags/資產擠在左下） | **頂部主分頁**：劇本 / 資產 / 敘事地圖 / 個性化 / 發布 / 設定 |
| 劇本編輯 | 場景清單 + 指令列 + 右側可開預覽 | **三欄常駐**：結構樹 ｜ 事件卡片 ｜ 即時預覽＋檢查器 |

## ❓ 決策 1：是否維持「Markdown 手寫友善 + 雙向相容」？

這是**最影響形狀的決定**。

- **維持（建議）**：所有新指令都必須能手寫、且 parse→write→parse 往返穩定。代價：鏡頭/粒子等複雜參數的 DSL 會變長，但作者仍可用純文字寫作、可 git diff、可用任何編輯器。
- **放棄**：改用 JSON/專屬格式，GUI 為唯一入口。好處是複雜參數好表達；代價是丟掉織夢最大的差異化，且現有四個劇本要遷移。

> 我的立場：**強烈建議維持**。它是織夢相對 LetsGal 的核心優勢，且我們已有完整往返測試護欄。

---

## ❓ 決策 2：是否引入「章節 → 片段」兩層結構？

現況是扁平 `scenes/*.md`。參考圖左側是 `章節 → 片段`（圖四統計「5章節 1分支 3片段」）。

- **方案 A（建議）：輕量分層** — 用資料夾或 `story.json` 的 `chapters` 陣列把現有場景分組；場景檔不動、DSL 不變。改動小、向後相容。
- **方案 B：完整重構** — 場景升格為「片段」，章節成為一級實體，含入口/終止/返回入口章節等語意（對應圖二的「終止章節/返回入口章節」）。功能完整但動到資料模型、存檔、流程圖。

> 影響：決策 2 會連動指令「調用片段 / 終止章節 / 返回入口章節」是否可行。

## ❓ 決策 3：立繪定位是否從「三格」改為「座標＋錨點」？

圖三是完整的定位編輯器（位置預設 左/中左/中/中右/右、錨點、X/Y%、尺寸）。

- **方案 A（建議）：漸進** — 保留 `left/center/right` 語意（既有劇本不壞），**新增**具名位置預設 + 自由 `x/y%` + 錨點 + `scale`。`@show 小鈴 center` 照舊；`@show 小鈴 pos=35,2 anchor=left_top scale=0.8` 為進階。
- **方案 B：全面改座標** — 乾淨但既有劇本全部要改。

> 需要引擎改動：`CharacterLayer` 從固定 CSS 槽位改為可定位容器。

## ❓ 決策 4：變量模型要擴充到什麼程度？

Phase 7a 已有 `{ type, default, label }`。圖四還有：

- **用途**（計數 / 開關…）→ 🔶 建議納入（純標註，利於篩選與檢查）
- **存檔範圍**：當前存檔 vs **跨存檔**（全域，如「遊玩天數」「存檔讀取次數」）→ 🔶 建議納入（需引擎與 SaveManager 支援全域儲存）
- **per-角色變量**：如「好感度」對 4 個角色各一份 → 🔶 建議納入（大幅簡化戀愛系統寫法）

## 1. 版面架構（吃掉原 Phase 6）

**頂部主分頁**取代目前的側欄擠壓：

```
劇本 ｜ 資產 ｜ 敘事地圖 ｜ 個性化 ｜ 發布 ｜ 設定
```

- **劇本**：左（結構樹，可搜尋）｜中（事件卡片）｜右（即時預覽 ＋ 檢查器）
- **資產**：左（角色/場景/BGM/音效/語音/總覽）｜中（編輯區）｜右（預覽＋引用）
- **敘事地圖**：左（變量管理 / 分支選項）｜右（地圖畫布）
- 🔶 **個性化**：遊戲外觀主題（文字框樣式、字體、配色）
- **發布**：現有 ZIP 匯出 ＋ 🔶 一鍵產生可上傳的網頁版
- **設定**：編輯器偏好

> 原「問題 / Flags」面板：問題→劇本頁右側檢查器分頁；Flags→併入敘事地圖的變量管理。

## 2. 三大分區規劃

### A. 劇本編輯（圖一）

- **左：結構樹** — 章節/片段、搜尋、顯示該章節出場角色頭像、拖曳排序。
- **中：事件卡片** — 行號、依類型著色、拖曳、🔶 快速預設鈕（如「等待」的 200/500/1000）、🔶 場景卡片內嵌縮圖、🔶 多選與批次操作、🔶 摺疊 if 區塊。
- **右：即時預覽（常駐）＋ 檢查器**
  - 預覽**只顯示游標所在指令的當下畫面**（不自動播放），按「▶ 運行」才播——**這是與現有 PreviewPanel 最大的差異**，需要引擎支援「靜態求值到第 N 條指令」。
  - **檢查器**：選取指令後在此編輯細部參數（卡片只放常用），對應圖一右下「設定文本參數」。

### B. 資產編輯器（圖三）

- 類別：角色 / 場景 / BGM / 音效 / 🔶 **語音**（目前缺）／資源總覽
- 角色：列表（頭像＋表情數）、**表情管理（含縮圖預覽 — Phase 3 已標記待補）**、位置與錨點編輯器、預設尺寸、🔶 屬性模板
- 右側：角色預覽（可切背景圖/深色/淺色/棋盤）、**資源引用**（哪裡用到）
- 🔶 **游離資產偵測**（圖三的「⚠1個游離」）、🔶 資產改名/取代、🔶 搜尋

### C. 敘事地圖 ＋ 變量管理（圖四）

- 地圖：章節主幹、**分支節點顯示選項內容**、**未引用片段**（黃色虛線）、連線圖例、縮放/Fit
- 變量管理：清單（用途/存檔/預設值）、搜尋、篩選、新建/編輯/移除、🔶 per-角色展開
- 🔶 **變量寫→讀連線**（圖四圖例有）：顯示哪個節點寫、哪個節點讀

## 4. 🔶 我額外建議納入的（你的描述未提，但值得考慮）

1. **全域搜尋** — 跨場景找台詞/角色/變量（圖一左上有搜尋，但只搜結構）
2. **自動存檔**（圖一狀態列「自動保存已開啟」）＋ 🔶 本地版本歷史
3. **資產引用追蹤與游離偵測** — 改名/刪除前知道影響範圍
4. **未引用片段偵測**（圖四已有）
5. **語音資產 + 對話綁語音**
6. **狀態列**：專案路徑、自動存檔狀態、版本（圖一底部）
7. **鍵盤操作**：目前只有 Ctrl+S/Z/Y，建議補新增指令、跳轉、搜尋
8. ⚠️ **不建議**：擴展方法/外掛系統、雲端協作 — 與「純靜態、免打包」衝突

## 5. 建議實作順序

> 原則：**先版面骨架 → 再把功能長進去**（資料層 Phase 1–7 已穩，改版面不動搖它）。

- **S1 版面骨架**：頂部主分頁 + 劇本三欄（含常駐預覽與檢查器骨架）。不加新功能，只搬家。
- **S2 資料模型**：依決策 2/3/4 擴充（章節、定位、變量）。含往返測試護欄。
- **S3 資產編輯器**：語音、表情縮圖、位置錨點編輯器、引用追蹤/游離偵測。
- **S4 敘事地圖 + 變量管理**：分支節點、未引用、圖例、變量 CRUD。
- **S5 演出指令補完**：文本參數 → 帷幕 → 鏡頭 → 精靈動畫 → 浮動文字 →（視頻/粒子視意願）。
- **S6 體驗**：全域搜尋、自動存檔、狀態列、快捷鍵。
