## ✅ 決策 1（已定）：三種表現形式共存 — AST 為核心的轉譯層

**採用使用者提案**：圖形編輯 / Markdown 手寫 / JSON 機器格式，透過同一個 AST 共存。

**現況：已完成三分之二。** 織夢早就是 AST 為核心的架構：

```
   Markdown  ⇄  【AST：{meta, instructions}】  ⇄  圖形編輯器
                        ↓
                   StoryEngine 執行
```

- `SceneParser.parse(md)` → AST；`MarkdownWriter.write(ast)` → md（往返已測，59 場景 0 不穩定）
- `SceneEditor` / `InstructionRow` **直接編輯 AST**（不是改文字）
- `StoryEngine` 執行 AST

**要補的**：
1. `SceneJson.parse/stringify` — 第三支 serializer（AST ⇄ JSON）
2. 編輯器**檢視切換**：卡片（GUI）／ Markdown 原文 ／ JSON（對應圖一右上 `✏️ ☰ {}`）
3. **往返護欄擴充**：`MD → AST → JSON → AST → MD` 必須穩定，納入既有 59 場景回歸測試

**效益**：複雜指令（鏡頭/粒子）在 GUI 編輯，作者不必面對長字串；需要時仍可切到 MD 手寫或 JSON 給工具讀。

### ❓ 決策 1b：磁碟上誰是唯一真相？（待你拍板）

- **方案 A（建議）：Markdown 為唯一真相**，JSON 為匯出/匯入與工具交換格式。保住 git diff 友善與手寫；無同步衝突。
- **方案 B：JSON 為唯一真相**，MD 為匯出/匯入。機器精確，但丟掉 git 友善與手寫直覺，四個劇本需遷移。
- **方案 C：兩者皆可為真相（依副檔名）** — `.md` 與 `.json` 場景並存，各自為政。彈性最大，但兩套格式都要維護、Linter/流程圖都要同時支援。

> ⚠️ 不建議「兩份同時存在並互相同步」——那是兩個真相，必然產生衝突。

## ✅ 決策 3（已定）：漸進式座標＋錨點

依使用者定義：
- **錨點（anchor）** = 圖片自身的原點位置（左上 / 正中 / …），決定「圖片以哪一點對齊到座標」
- **位置（position）** = 該錨點在螢幕上的 X/Y 座標（百分比，可在編輯器拖曳設定）
- **尺寸（size/scale）** = 圖片縮放

**做法（漸進，既有劇本不壞）**：
- `左/中左/中/中右/右` 保留為**具名位置預設**（內部就是一組 X/Y 座標，可在資產編輯器調整）——這正是圖三上方那排預設
- `@show 小鈴 center` 照舊可用；進階寫法 `@show 小鈴 pos=35,2 anchor=left_top scale=0.8`
- 引擎：`CharacterLayer` 從固定 CSS 槽位改為**可定位容器**（transform + transform-origin 對應錨點）

## 2. 三大分區規劃

### A. 劇本編輯（圖一）

- **左：結構樹** — 章節/片段、搜尋、顯示該章節出場角色頭像、拖曳排序。
- **中：事件卡片** — 行號、依類型著色、拖曳、🔶 快速預設鈕（如「等待」的 200/500/1000）、🔶 場景卡片內嵌縮圖、🔶 多選與批次操作、🔶 摺疊 if 區塊。
- **右：即時預覽（常駐）＋ 檢查器**
  - 預覽**只顯示游標所在指令的當下畫面**（不自動播放），按「▶ 運行」才播——**這是與現有 PreviewPanel 最大的差異**，需要引擎支援「靜態求值到第 N 條指令」。
  - **檢查器**：選取指令後在此編輯細部參數（卡片只放常用），對應圖一右下「設定文本參數」。

### B. 資產編輯器（圖三）

- 類別：角色 / 場景 / BGM / 音效 / 🔶 **語音**（目前缺）／資源總覽
- 角色：列表（頭像＋表情數）、**表情管理（含縮圖預覽 — Phase 3 已標記待補）**、位置與錨點編輯器、預設尺寸、🔶 屬性模板
- 右側：角色預覽（可切背景圖/深色/淺色/棋盤）、**資源引用**（哪裡用到）
- 🔶 **游離資產偵測**（圖三的「⚠1個游離」）、🔶 資產改名/取代、🔶 搜尋

### C. 敘事地圖 ＋ 變量管理（圖四）

- 地圖：章節主幹、**分支節點顯示選項內容**、**未引用片段**（黃色虛線）、連線圖例、縮放/Fit
- 變量管理：清單（用途/存檔/預設值）、搜尋、篩選、新建/編輯/移除、🔶 per-角色展開
- 🔶 **變量寫→讀連線**（圖四圖例有）：顯示哪個節點寫、哪個節點讀

## 5. 建議實作順序

> 原則：**先版面骨架 → 再把功能長進去**（資料層 Phase 1–7 已穩，改版面不動搖它）。

- **S1 版面骨架**：頂部主分頁 + 劇本三欄（含常駐預覽與檢查器骨架）。不加新功能，只搬家。
- **S2 資料模型與轉譯層**：JSON serializer（AST ⇄ JSON）＋ 檢視切換（卡片/MD/JSON）；章節輕量分層；立繪座標＋錨點；變量 usage。
  護欄：`MD → AST → JSON → AST → MD` 往返穩定，納入 59 場景回歸測試。
- **S3 資產編輯器**：語音、表情縮圖、位置錨點編輯器、引用追蹤/游離偵測。
- **S4 敘事地圖 + 變量管理**：分支節點、未引用、圖例、變量 CRUD。
- **S5 演出指令補完**：文本參數 → 帷幕 → 鏡頭 → 精靈動畫 → 浮動文字 →（視頻/粒子視意願）。
- **S6 體驗**：全域搜尋、自動存檔、狀態列、快捷鍵。
