## 1. 版面架構（取代原 Phase 6）

```
劇本 ｜ 資產 ｜ 敘事地圖 ｜ 個性化 ｜ 發布 ｜ 設定
```

- **劇本**：左（結構樹/搜尋）｜中（事件卡片）｜右（預覽＋檢查器）
- **資產**：左（角色/場景/BGM/音效/語音/總覽）｜中（編輯區）｜右（預覽＋引用）
- **敘事地圖**：左（變量管理 / 分支選項）｜右（地圖畫布）
- **個性化**：遊戲外觀主題（文字框、字體、配色）
- **發布**：ZIP 匯出（已有）＋ 網頁版產出
- **設定**：編輯器偏好
- **狀態列**：專案路徑、自動存檔狀態、版本

> 原「問題／Flags」面板解散：問題 → 劇本頁檢查器分頁；Flags → 敘事地圖的變量管理。

## 2. 關鍵新能力：預覽的「靜態求值」

圖一的右側預覽**只顯示游標所在指令的當下畫面**，按「▶ 運行」才播放。
這與現有 PreviewPanel（從頭播）本質不同，需要引擎新增：

> **靜態求值到第 N 條指令**：不播動畫、不等待、不觸發音效，
> 只計算「執行到第 N 條時的畫面狀態」（背景/立繪/文字/旗標），一次套用。

這是本計畫**最關鍵也最有技術含量**的一項，列為 S3 獨立階段。

## 6. 風險與注意

- **S3 靜態求值**：指令有副作用（音效、動畫、等待）。需在引擎區分「求值」與「播放」兩種模式，或讓指令宣告自己是否可靜態套用。設計不當會與正式遊玩行為漂移——**必須與 GameRuntime 共用同一份指令語意**，不可另寫一套。
- **S2 立繪定位改造**：`CharacterLayer` 從 CSS 槽位改為可定位容器，會動到遊玩端。四個既有劇本為回歸基準。
- **粒子效果**：純 CSS 難做好，可能需 Canvas；是本計畫最重的單項，建議放最後，做不動可砍。
- **DSL 長度**：鏡頭/粒子參數多，MD 會變長。緩解：GUI 為主要編輯方式，MD 仍可讀可手寫。
