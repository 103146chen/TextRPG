# 織夢引擎 · 打磨計畫

參考 LetsGal Studio(avg-plus/light-engine)的優點，在**不破壞「純靜態、免打包」核心價值**的前提下，逐步強化編輯器體驗與引擎健壯性。

> 打磨前還原點：commit `3e1f359`（`chore: 建立打磨前還原點…`）。
> 任何階段出錯可 `git reset --hard <該階段前的 commit>` 回退。

## 貫穿全程的原則

1. **絕不破壞純靜態、免打包**——不引入 build step；需第三方時只 vendor 單檔 ES module。
2. **絕不破壞既有劇本相容性**——現有四劇本（demo_story / cheng_zi / chu_shi_biao / hong_men_yan）為回歸測試基準，每階段結束都要能正常遊玩。
3. **先立抽象、再加實作**——「場景來源 / 資產解析 / 儲存後端」先抽介面，後續功能接介面，避免返工。

## Phase 1 — 引擎健壯性

趁未動大結構，先補兩個引擎層隱患。

| 項目 | 現況問題 | 做法 | 檔案 |
|------|---------|------|------|
| 選項 `+=`/`-=` | `selectChoice` 的 `set` 只能覆寫；程式碼註解自承此限制 | `#parseInlineObject` 支援 `charm: += 1`；`selectChoice` 套用時比照 `#applySet`。**舊語法 `{ charm: 1 }` 維持賦值語意** | `SceneParser.js`、`StoryEngine.js` |
| 存檔易錯位 | `serialize()` 存原始 `pc`，劇本一改舊存檔跳錯行 | 改存 `{ sceneId, 最近 label, 距 label 步數, flags, storyHash }`；載入時 `storyHash` 不符則提示但盡力復原 | `StoryEngine.js`、`SaveManager.js` |

驗證：`chu_shi_biao` 跑各分支；存檔→改劇本→讀檔確認提示。風險：低。

### Phase 1 完成摘要（commit 見下）

- **選項 `+=` / `-=`**：`{ charm: += 1 }` 現在會做增量；舊語法 `{ charm: 1 }` 仍是賦值。涵蓋解析、引擎套用、Markdown 輸出、編輯器欄位、Flag 檢視器五處。
- **存檔健壯化**：存檔加入 `sceneHash`（FNV-1a）與 `branchStack`；讀檔時劇本未變則精確還原，已變則夾範圍並提示，避免落在錯位指令。
- **修復既有 bug**：`loadState` 過去未還原 `_branchStack`，在 `:: if` 區塊內存檔再讀取會誤觸 `else`/`elif`；已修正。
- **BOM 加固**：`SceneParser.parse` 開頭去除 BOM，避免未來直接餵字串（即時預覽）時解析錯誤。
- **驗證**：Node 單元測試 17/17；59 個場景 Markdown 往返 0 不穩定；瀏覽器實測 demo_story 選項分支正確、cheng_zi 正常開場。

## Phase 2 — 編輯器內即時預覽

`StoryEngine` 建構子加可插拔 `sceneLoader` / `metaLoader` / `assetResolver`（預設維持 `fetch`，遊玩端不受影響）。新增 `preview.html`，編輯器以 `<iframe>` + `postMessage` 傳入記憶體專案資料與起始位置；`SceneEditor` 每列加「▶ 從這裡試玩」。資產經 File System Access API 轉 blob URL。

### Phase 2 完成摘要

分五個子步驟，每步獨立 commit、每步驗證遊玩不被改壞：

- **2a** `StoryEngine` 加可插拔 `sceneLoader`/`metaLoader`（預設 fetch）+ `startAtScene(sceneId, pc)` + `clearSceneCache`。
- **2b** `CharacterLayer`/`BackgroundLayer`/`AudioManager` 加可插拔 `resolveAsset`（預設走路徑）。
- **2c** 抽出共用 `GameRuntime`（引擎↔UI 接線單一來源），`main.js` 改用之；行為零變更。
- **2d** `preview.html` + `src/preview.js`：postMessage 橋接，資產以「向父視窗要 Blob → 本頁 object URL」取得（同源安全）。
- **2e** 編輯器整合：`PreviewPanel`（右側停靠 iframe）、`FileSystem.readResource`、`SceneEditor` header「▶ 預覽此場景」、每個指令列「▶ 從這裡試玩」。

**驗證**：Phase 1 單元測試持續 17/17；瀏覽器實測 GameRuntime 重構後 demo_story 選項→flag→if 分支正確；預覽 harness 端到端確認未存檔內容即時反映、資產經 Blob 載入、選項/goto/`+=`/結局正確、`startPc` 從指定指令開播；真編輯器確認 PreviewPanel 正常建立。

> 註：完整「開資料夾→預覽」需 File System Access 的使用者手勢，無法在自動化中觸發，改以假 project 的 harness 等效驗證。

## Phase 3 — 資產管理 UI

`FileSystem.js` 加 `writeAsset` / `listAssets`。新增資產面板：拖曳匯入 `backgrounds/characters/bgm/se`、縮圖、試聽。擴充 `StoryManager` 角色表情視覺化對應。自動補完改讀真實資產庫。

### Phase 3 完成摘要

- `FileSystem` 加 `writeResource` / `deleteResource`（`readResource` 於 Phase 2e 已加）。
- `StoryProject` 加 `importAsset` / `deleteAsset` / `refreshResources`，發出 `resources-updated` 通知。
- 新增 `AssetPanel`（側欄「資產」分頁）：背景／立繪／BGM／音效四區塊，支援**拖曳與挑檔匯入**、圖片**縮圖**、音訊**試聽**、**刪除**。
- 匯入/刪除後 `project.resources` 即時刷新，並連動場景編輯器的背景/BGM/立繪下拉選單（`resources-updated` 觸發重繪）。

**驗證**：harness（真 StoryProject + 假 fs）確認四區塊渲染、9 張縮圖全載入、匯入 new_bg.svg 後計數 3→4 且 resources 同步、刪除後 4→3；真編輯器確認「資產」分頁存在可切換、AssetPanel 正常掛載。

> 註：角色表情對應沿用既有 `StoryManager`（下拉選單，資料來源為現在可匯入的立繪庫）；視覺化縮圖挑選器列為後續可選加強。

## Phase 4 — 跨瀏覽器 + 儲存後端抽象

`ProjectFileSystem` 抽成介面，兩實作：`FSAccessBackend`（現行）、`MemoryBackend`（ZIP 匯入→記憶體編輯→ZIP 匯出，可選 IndexedDB 持久化）。Vendor 單檔 `fflate`。不支援 FS Access API 時自動切 `MemoryBackend`，取代硬擋畫面。

## Phase 6 — 編輯器版面/分頁改善（延到最後）

**問題**：`問題 / Flags / 資產` 三個分頁擠在窄側欄下方約 55% 的小區塊（場景清單佔上方 45%），資產縮圖尤其難用。

**做法（到時再定，皆在既有 `.side-tab`/`.side-panel` 上加強）**：場景清單與分頁區之間加可拖曳分隔線調整高度／分頁區可展開借用主區空間／資產面板支援彈出較大浮動視窗。

**判斷**：純版面（DOM+CSS）重排，與 Phase 4/5 零相依、零返工，適合最後做。
